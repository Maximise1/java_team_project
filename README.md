## Командный Java проект

Чтобы запустить проект необходимо выполнить следующие команды:

```
git clone https://github.com/Maximise1/java_team_project
./gradlew run --console=plain
```

### Архитектура проекта

Проект содержит 2 базовых класса:

1. Main - класс с которого начинается исполнение программы. Создаёт сущность Application класса и запускает приложение.
2. Application - класс приложения. Имеет метод run, содержащий бесконечный цикл приложения и поле типа Container.

В проекте имеется 7 пакетов:

1. count - пакет, содержащий классы, используемые при многопоточном подсчете кол-ва сущностей в массиве.
2. db (database) - пакет, содержащий реализацию кастомного класса (Bus) и репозитория BusRepository.
3. di (dependency injection) - содержит класс Container в котором определены основные зависимости (HashMap с обработчиками команд, парсер, репозиторий), а также enum с типами команд, интерфейс обработчика команды и класс Command.
4. input - содержит классы для работы с вводом пользователя (парсер команд, чтение из файла, консоли, заполнение массива случайными элементами).
5. output - содержит классы для вывода информации в консоль и файл (вывод списка команд, вывод массива классов в консоль, запись в файл).
6. sort - содержит класс сортировщика (Sorter) и обработчика команды sort (SortHandler).
7. util - содержит utility классы. CustomArray - наша имплементация класса Array и DataValidator - валидатор данных (проверяет переданные поля классов Bus на соответствие стандарту).

### Структура репозитория

Данный репозиторий содержит 7 dev веток, по одной для каждой задачи (задачи описаны в конце этого файла), и одну ветку main.
dev ветки содержат код, реализующий соответствующие задачи. Векта main содержит актуальную версию приложения.
Коммиты делаются в соответствующие ветки задач. Когда задача выполнена, делается pull-request в main. Его должен проверить и замерджить тим лид.

## Основное задание

Написать приложение, которое будет реализовывать алгоритм сортировки выбранных классов. 
Приложение должно быть выложено на гитхаб/гитлаб, количество веток с кодом должно соответствовать 
количеству участников (минимум), все ветки в итоге должны быть смерджены в master/main ветку. Вся 
архитектура и код стайл должны соответствовать конвенциям языка Java. Программа должна выполняться 
в цикле. Выход из цикла возможен только путем соответствующего выбора пользователя. Пользователь 
должен иметь возможность выбирать варианты заполнения исходного массива данных (из файла, рандом, 
вручную) и его длину.
В программе должен использовать паттерн стратегия. Сортировать необходимо кастомные классы - 
класс должен иметь реализованный паттерн Builder. Для вводимых данных (в тч из файла) должна 
производиться валидация данных.
Сортировка должна быть базово реализована по всем 3 полям.

Примеры классов:
1. Автобус (Номер, Модель, Пробег)
2. Пользователь (Имя, Пароль, Почта),
3. Студент (Номер группы, Средний балл, Номер зачетной книжки)
4. Автомобиль (Мощность, Модель, Год производства)
5. Бочка (Объем, Хранимый материал, Материал из которого изготовлена)

Классы могут быть любыми, в том числе те, что перечислены здесь. Выбрать необходимо 1 класс.

### Дополнительное задание 1.

Дополнительно к основным сортировкам реализовать эти же алгоритмы сортировки таким образом, что 
объекты классов будут сортироваться по какому-либо числовому полю: объекты с четными значениями 
этого поля должны быть отсортированы в натуральном порядке, а с нечетными – оставаться на исходных позициях.

### Дополнительное задание 2.

Реализовать функционал для записи отсортированных коллекций/ найденных значений в файл в режиме добавления данных.

### Дополнительное задание 3.

Заполнение коллекций должно осуществляться посредством стримов. Коллекции для заполнения должны быть кастомными.

### Дополнительное задание 4.

Реализовать многопоточный метод, подсчитывающий количество вхождений элемента N в коллекцию и выводящий результат в консоль.

### Общее требование.

Все классы должны базово реализовывать сортировку по всем 3 полям. Для кастомной сортировки разрешено 
использовать компаратор. Запрещено применять готовые реализации сортировки, поиска и паттернов.

В программе также должны быть реализованы тесты к написанному коду. Классические тестовые библиотеки 
использовать не обязательно (но можно), так как мы их не изучали, достаточно просто тестов в отдельных классах, реализованных руками.
Результат прикрепить в виде ссылки на Github/Gitlab.

## Задачи

1. Реализовать многопоточный метод, подсчитывающий количество вхождений элемента N в коллекцию и 
выводящий результат в консоль. (Пожалуй, самое трудное задание.) Работаем с классом CounterHandler. (Стас)
2. Реализовать класс Автобус с паттерном Builder. Работаем с классом Bus. (Никита)
3. Реализовать парсер команд пользователя. Работаем с классом CommandParser. Какими могут быть команды
прописано в HelpHandler. (Максим)
4. Реализовать парсинг автобусов из файла и консоли. Работаем с классами ConsoleReader, FileReader и InputHandler. (Сабит)
5. Реализовать вывод автобусов в консоль и запись в файл. Работаем с классами ConsolePrinter, FileWriter и OutputHandler. (Артём)
6. Вставить релизованный код сортировки в программу. (Максим)
7. Переделать реализацию класса CustomArray. (Никита)
8. Поддержка SIGINT (Graceful shutdown) (Стас)
